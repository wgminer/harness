Chat Type Sprint

The assistant answers in VT323, and that face is Harness. The trouble is everything around it: headings that look like bold, a tight line for long replies, and four type families sharing one thread. This sprint keeps the face and reworks the system around it.

1

Map

Long-term goal. A 600-word reply in Harness is as easy to read as a page in a good book, and it still looks like it came from Harness.

Sprint questions.

  • Can VT323 carry a long, structured reply without tiring the reader?
  • Can someone tell a heading from a bold phrase in a face with one weight?
  • Should the thread have one voice for the machine and one for the person, or one for everything?
  • How many sizes does the chat UI actually need?

What the code says

1

Headings look like bold. VT323 has one weight, so strong and .md-heading both become an underline at body size. A heading and a bold phrase are the same mark.

2

The reply line is tight. 21px on a 24px line is a ratio of 1.14. The user card next to it runs at 1.5. Long replies read as a dense block.

3

Secondary text all collapses to 12px. --font-size-caption and --font-size-ui are both 12px. Tool cards stack muted color and 80% opacity on top of that, which is the faintest text in the app.

4

Too many tokens for the values. snug, normal and body are all 24px. tight, caption, ui and compact are all 16px. Stray sizes (10, 11, 13, 0.65rem, 0.7rem, 0.95rem) sit outside the scale.

5

Two tokens don't exist. --font-size-xs (the selection-image footer and status) and --font-mono (four places in chat and settings) are never defined. The footer inherits its size instead of shrinking.

6

Comments still describe the serif. chat.css talks about an "18px serif reply" and a "title-size serif". The face moved from Newsreader to VT323 on Oct 11 and the notes stayed.

How might we

  • make a heading read as a heading in a face with one weight?
  • give long replies room to breathe without losing the CRT?
  • make the machine's chrome (tools, ticker, time) sound like the same machine as the reply?
  • cut the scale to steps a person could name from memory?

Target

Reading a long, structured reply that arrived after two tool calls. It's where every problem above shows up at once, and it's what people come back to Harness for. Short replies already work.

B. Two voices

The person speaks in SF, the machine in VT323. Tool cards, the ticker and the time move into VT323. Bold becomes bright intensity, the way a terminal shows it, and the reply line opens up to 28px.

C. Pixel display, sans body

VT323 sets headings and one-line replies. Anything longer reads in SF at 16/26 with real bold. Character lives in the headlines; paragraphs are for reading.

Storyboard for the test

  1. The tester opens Harness on a conversation they didn't write.
  2. They read the question in the user card and see two tool cards finish.
  3. The long reply is on screen: a heading, a decision in bold, a list, a table, a code block and a link.
  4. They answer four questions from the reply, out loud, without scrolling back to the question.
  5. The interviewer switches direction with the edge tag and asks the same kind of question about a second reply.
  6. They switch to the short reply and say whether it still feels like the same app.

Where Parakeet stands

Decision: ship Parakeet as opt-in in 0.9, then make it the default once the download flow is solid. You agreed on that in the Dictation engine 1:1 on Oct 17. Apple Speech stays as the fallback for anyone who skips the 450 MB download.

It runs on-device, and on long clips it's about three times faster than Apple Speech:

ClipApple SpeechParakeet
10 s note0.9 s0.6 s
45 s ramble2.8 s1.0 s
3 min memo9.4 s3.1 s

What's left

  1. Show download progress in Voice settings instead of a spinner.
  2. Fall back to Apple Speech when the model file is missing or corrupt.
  3. Flip the default for transcription.engine in both types.ts and settings.rs.

The default change itself is two lines:

// src/shared/types.ts
transcription: { engine: "parakeet", cleanup: { enabled: true } }

The first two are the real work. Once they land, the flip is safe to ship on its own.

Yes. Harness Dev is on Parakeet. The installed app still uses Apple Speech until you switch it in Voice settings.

Risks to watch

      
    
        
  • Bright-intensity bold is subtle in light mode. Black on #3b3b3b may not read as emphasis. If it fails, light mode gets the underline back.
    • 
        
  • VT323 at 18px for chrome. Pixel faces break up at small sizes on non-Retina screens. 18px is the floor.
    • 
        
  • Mixed faces in one line. Inline code (SF Mono) and links inside VT323 prose need to sit on the same baseline. Check on real replies, not just this one.
